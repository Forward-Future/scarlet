# Contributing to Scarlet

For a bug report, include your Scarlet version, operating system, what you tried and what happened. A small project made from generated media makes an editing bug easier to reproduce. Keep personal footage, transcripts, credentials and machine-specific paths out of attachments. [Open an issue](https://github.com/Forward-Future/scarlet/issues) · [Report a vulnerability privately](SECURITY.md)

For a code change, branch from the public `main`, keep the pull request focused and describe how you tested it. Run `pnpm typecheck` and the tests for the packages you changed. If the change affects desktop behavior, include the operating system you tested. The development guide covers building, running tests and packaging the native app. [Development guide](docs/development.md)

Changes to how Scarlet edits video should include an evaluation with generated or shareable inputs. [Agent design guide](docs/AI-AGENTS.md) · [Editing evaluations](evals/README.md)

The project’s code of conduct applies in issues, pull requests and discussions. [Code of conduct](CODE_OF_CONDUCT.md)
