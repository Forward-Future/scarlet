# Scarlet

Scarlet is a desktop-only video editor for macOS, Windows and Linux. Open projects, demonstrate features, take screenshots, and verify interface changes in the native Scarlet application window. Do not open or publish a browser version, including a localhost demo or an in-app browser preview.

When the maintainer asks to land a PR, run the checks for the change and inspect GitHub’s current merge requirements for `main`. Merge the approved head as soon as those requirements are satisfied (`gh pr merge <pr> --merge --match-head-commit <sha>`). With no required checks, merge immediately after local verification. Optional checks and post-merge builds run independently. Resolve any conflict, check the updated head, and verify the PR reached `main`. If the request includes a deployment or a packaged build, verify that outcome too. A request to drain the maintainer’s queue covers only their own PRs that they explicitly queued for merge.

If a required check holds an otherwise ready PR for two minutes, inspect its workflow and runner status for that head. If the workflow is disabled, the status is missing, or the job is stuck waiting for a runner, run the equivalent check on the approved head or verify an existing result for that SHA. Remove just the stalled requirement if needed to merge. Restore a requirement lifted for a temporary runner delay after the merge, preserving concurrent rule changes. Report which check you removed and what you verified. Fix genuine test failures and verify the updated head.

Starting a chat does not require opening Scarlet. Keep code work and automated tests headless until the task needs the native interface. For work on the installed release, reuse the regular Scarlet window.

Silence only the Scarlet instance under test. Leave system volume, output devices, and other apps’ audio unchanged. For screenshots, use a muted native background preview and capture only the requested window or panel. On Windows, use a separate, noninteractive desktop and a disposable WebView2 profile. Launch with `--mute-audio` and verify the flag on that instance’s running WebView2 process before testing or capturing. On Linux, run native UI tests on a private Xvfb display with isolated audio. Leave the user’s desktop, window focus, mouse, and keyboard untouched throughout.

Share one native preview across chats. Before launching, check for a running dev or demo session in the checkout you need. Reuse it if it is idle and matches the requested mode. If another chat is using the preview, wait your turn. When a preview needs to be started, use `pnpm desktop:dev` for the real project library or `pnpm desktop:demo` for the isolated sample interview. Close a temporary preview you started and stop its dev command after verification, unless the user wants it left open for review.

The React code in `apps/web` is the embedded Tauri renderer. Vite is its development asset server, and `apps/server` is the headless engine. Neither is a user-facing way to launch Scarlet.

Use the shared native preview for uncommitted changes. Create a standalone review app when the task requires testing a packaged build or the editor asks for one. Give it a distinct name and bundle identifier.

Prefer hardware acceleration for local transcription and playback caching. Honor explicit hardware settings and keep a working CPU fallback. Verify device selection and word timings or playback correctness on a separate fixture when changing these paths.

Keep the interface mostly black, white, and gray. Use small color accents for branding, voice, and status. Use the project's own footage for thumbnails and avoid decorative background images.

The editor chose a few quiet touches, and they stay. Ambient light: the footage's own colours glow softly round the player and under the timeline, following the picture (`AmbientLight`); it is the one light from the footage, not a background image. An edit applied while the editor watches lands with a moment on the timeline: its marker pops in with one ring, after a cut's red closes up where the footage came out. An edit the editor rejects leaves as quietly: its band fades where it is and its marker shrinks away, and nothing else on the timeline moves. While the mic records, a ring round it moves with the voice. Timeline pictures fade in as they load, the card rises into place as it opens, and the playhead glides to a new position on a seek and jumps instantly across footage the player skips. A project's card flips through a few frames of its footage while the pointer rests on it. With motion reduced, none of it moves.

Use the shared `PreferenceSelect` for dropdown fields throughout the renderer, including compact toolbar and review pickers.

The simple view is one conversation on the left (`.simple-thread`), then the player with its card and timeline. The Transcript, from the ⋯ menu, is a column of its own on the right of the player (`.simple-transcript-rail`), never in the chat: the chat stays in view beside it, a message sent leaves it open, and its × or Esc closes it. It is headed as the chat is (its name and the ×), then a plain search field, then the whole transcript, set in the chat's type under a dim time (and the voice, where there are several): no figures, key box, notes or offers to transcribe other files. Words are dim, the sentence the playhead is in is bright, and the word it is on is lit. A click on a word places the playhead there; it doesn't play. Search underlines every match, says "2 of 9", and Enter places the playhead on the next match (Shift+Enter the one before). Chosen words (double-click or drag) put one quiet line under the heading: their time, Ask about this and Clear. There is no list of edits beside the chat. Every request for an edit is in the conversation in the order asked, headed by the editor's words, and it opens at the latest. A request about one cut or edit sits under that cut's or edit's row while Scarlet works on it or when it stopped early, and leaves once it has changed that cut or edit: what it did is there. Nothing in it is hidden or moved when a cut or an edit opens. The chat holds what was said and done, not the dialogue. While a cut or an edit is open, nothing sits over the message box: its transcript icon is on its card. Scarlet's note on a cut or an edit is on its card, once, and never repeated in the chat. The message box talks to the cut or edit that's open, and carries a tag before the text that says which ("Cut at 2:05", "Edit at 0:11"). A tag with a place (a cut, an edit, a moment, a stretch marked on the ruler) sits on a line of its own on top of the box, under the queue's tray (`.composer-aim-line`), so the box keeps its width for the words. A timed cut or edit, or a moment picked on the timeline, shows its time alone ("0:09", never "At 0:09"), and a marked range shows its start and end times. Their full names are available on hover and to screen readers. Hovering over the tag or focusing it widens it to reveal the ×. The tag shrinks when neither applies, and reduced motion makes the size change immediate. The × clears that target and is always visible on touch devices. When a marked range accompanies another target, “+1” opens a list showing the range with its own ×. Escape closes the list and returns focus to “+1”. Hovering or focusing the tag lights the open passage and the marked stretch on the timeline. "Answer" and "Reply" stay words, since they say who the message goes to. An applied edit's tag reads as its row in the list does: at the row's time, and as a cut when it took footage out. A call of the pass that's waiting is tagged with its number instead ("Cut 2"), and the tag's line says after it where that cut is and where the playhead is now ("at 2:47 · Playhead 2:57"), paused or not. A request sent that way is headed with the same words in the chat and tagged with them in the queue. With nothing open the box answers Scarlet's question when one is waiting, tagged "Answer"; otherwise it starts a new edit. Empty for a new edit, it reads "Describe an edit, / skills", whole at the chat's 320px, with no keys beside it. `/` lists the skills (`.composer-skills`): what follows the sign filters it, ↑ ↓ light a row, Enter or Tab puts its name in place of what was typed, Esc puts it away. There are no templates (the editor took them out on 2026-11-18, to come back to later): a look or a transition to reuse is written in a skill, and `$` is plain text everywhere. On a skill's page, a `/skill` of the editor's in its instructions has a faint fill that doesn't move the text and says on hover what it is; words the library has no skill for, and tool names, stay plain, and the page's own message box has no `/` list. The editor chose the skill page's design too. Files dropped or pasted on the box ride on the next message instead of going into the project: one row each in a line on top of the box, nearest the box under the queue's tray, with the file's name and a × named Remove; a file still being added says so, and one that couldn't be says why. M, or the pen beside Full screen, pauses the video and marks the frame under the playhead (`PictureMarks`): a small bar at the picture's top left holds Draw, Box and Point (D B P), Undo (⌘Z) and Clear, with the frame's time and how many marks; a press that hardly moves puts a point. Marks are white with a dark edge, and numbered once there are several so the words can say which. Esc, M again or playing on ends the marking; the marks stay, shown whenever the player rests on their frame, and ride on the next message as a row of that same line, the frame's picture with its marks and "Marked frame 0:07", which goes back to the frame when pressed, with its × named Remove. Sent, the frame's picture with the marks drawn on it is one of the message's files, the marks' shapes and places go with it, and the request's band shows that picture before the editor's words. A new request starts on the whole video, whether the editor types, speaks or uses a slash command. A press or scrub on the timeline or a skip with ← → aims the new edit at that time at once, with no second press: the box shows its time in the tag. N also takes the current time, stops the video and puts the cursor in the box. A pause the editor makes (Space, the play button or a click on the picture) writes its time into an empty box as the start of the message ("0:04 "), as if they had typed it, with no tag; the message goes to that frame. With a cut or an edit open, nothing is written: the pause's time takes the place of the cut's or edit's in the tag, so the box shows one time, and the tag's full name still says which cut or edit the message goes to. A seek moves it while the box is empty, and playing on with nothing written puts back the cut's or edit's own time. The message is still that cut's or edit's, and Scarlet is told the frame the editor stopped on besides. While the box holds only that, the next pause or a seek moves it and playing on takes it out; words written after it keep it. Words chosen in the transcript and a stretch marked on the ruler stay through a press or a skip; N takes their place. That tag belongs to the box alone and stays at the chosen time while the message is written. The request's heading in the chat and its line in the queue omit it. An empty box drops the tag once the video plays or moves on. Looking around the timeline keeps a draft, an open cut or edit, and an answer aimed where they were. The × on the tag makes the message a new edit about the whole video instead. Backspace in an empty box does the same for any tag, a cut's or an edit's too, and ⌘Z in the empty box puts it back; a held Backspace that just emptied the box doesn't. A message being written stays aimed where it was, and its tag says where. Nothing above the box names it or offers to move it: that line is for screen readers only. While a pass still runs, a flagged cut Scarlet hasn't checked is not a call: it gets no dot or count until Scarlet asks about it. A call's number is the order it reached the editor in: Scarlet's asks as it makes them, then the cuts it never checked, in timeline order after them. A call keeps its number as later ones arrive, and it is the same on the timeline, on its card and in the pass's list. While the pass waits on calls, an edit of its request that asks for a look is numbered after them, in timeline order, and goes by that number in the list, on the timeline, on its card and in the box's tag ("Cut 6", or "Edit 6" when it took no footage out), so For you is one run of numbers. Every one of them keeps the number it was first shown under for as long as the pass waits, kept or not: a call or an edit that arrives later takes the next number, wherever it is in the video, and a number whose call or edit has gone isn't given again. A call sent back for revision can't be opened from the pass's list, but ↑ and ↓ step through it like any call: its card says Revising…, Queued or Needs your answer where the decisions were, and when its revision lands the card stays open on the new version. The chat can't be dragged under 320px. The editor chose this design. Get their approval before changing its layout or labels. `SimpleWorkspace.test.tsx` checks it.

In the simple view, an applied edit and a call a dialogue pass wasn't sure about open in the same card, right on top of the timeline (`.edit-card`), with nothing drawn between the card and the passage's band. The card is the same two rows for both (the editor chose it on 2026-11-21): what the edit did and Scarlet's note on the first, and under a faint rule the controls, Before/After and the transcript icon at the left and the decisions at the right. Before/After is one soft grey pill that reads Before and After, the side playing lit, with its key \ at the pill's end, named on hover ("Play Before (\)", then "Back to After (\)"); a press on it or \ switches sides. Every edit, suggestion and standalone comparison uses that same pill. A cut's transcript icon comes after it, with no text, named on hover ("Show transcript", then "Hide transcript"). A cut plays as the video runs now unless Before is lit. A click inside the red passage on the timeline plays from that point through the cut footage and lights Before by itself, with a flash. It stays lit until \ or the pill is pressed again, and the next cut opens unlit. An open cut or call plays its join and stops once, a moment after it. Play then carries on from where it stopped, and a press on the timeline plays on from that point: nothing stops the video again but the editor or its end, and what other cuts took out is stepped over on the way. A press on the open cut's row in the chat plays it again from the top, unlit, and doesn't close the card. After Keep, an applied edit's card has a small × named "Reject edit" on hover, as a call's card has (the editor asked for it back on 2026-11-18): it puts back just that edit. One × is one edit (the editor's decision, 2026-11-19): on a moment's card it is the edit the card is named for. An edit the engine put back leaves the timeline and nothing else moves (the editor asked on 2026-11-19, to see it go): its band fades where it is, on the timeline as it was and at the same zoom, and its card stays, with its note and Rejected and nothing to decide. The card doesn't go on by itself: ↑ ↓ step to the edits either side, Esc closes it, and play opens it as its row does, on the video as it runs now. One Scarlet is asked to put back goes on as Keep does, to the rest of its moment first. Whenever the engine knows exactly what the edit changed, it goes back at once and with no model (the editor asked on 2026-11-18): a cut's footage at its join (`putBackCut`), a look an edit gave its clips, in a change that set nothing outside the edits it named (`putBackLooks`), and a request whose every edit is rejected, which comes out whole as History's Undo takes it out; every other edit stays as it is (`POST /projects/:id/rejected-edits`). An edit the engine can't put back itself, or one a later edit changed, is a request to Scarlet instead, which reads "Reject edit", and its row says Rejecting… meanwhile. New kinds of edit get an engine put-back where one is exact, so the model is the exception. A rejected edit stays in its request's list of every edit, where it was, under its own words: a × where a kept one has its tick, "Rejected" where its amount was, dim. A press on its row shows it again (the editor asked on 2026-11-19): the timeline goes to where it was, with an outlined band that says Rejected over the video as it plays without it, and its card has its note and Rejected, with nothing to decide; the message box is aimed at it, Esc closes it and ↑ ↓ step to the edits either side. It has no dot, isn't stepped to and isn't counted in the sentence on what the request made. "Undo this" in the message box, aimed at the open edit, asks the same. A graphic's card says Graphic, and B-roll's says B-roll: footage, or a picture taken from the web, laid over the picture; anything else laid over it is an Overlay. B-roll from the web has a small icon after Before/After, where a cut has its transcript icon, named "Show source" and then "Hide source" on hover: it opens between the note and the controls, as a cut's passage does, with the page as Scarlet captured it and the part in the video lit, its address, which opens the page, and when it was captured, and it folds again on the next edit (the editor chose this on 2026-11-21). A call leads with its number ("Cut 2"), the same as on its line in the chat, and says on hover where its cut is ("Cut at 2:47"). A flagged edit still waiting on the editor leads with its place among the ones that are ("1 of 3"), since nothing else says how many are left, unless its pass still waits on calls: then it leads with its number among them ("Cut 6") and says its place on hover. It has no picker and no script icon: ↑ and ↓ step to the others. Revise and Keep are soft grey pills like Before/After, Keep a shade lighter, each with its key beside its label. Over the note, one bright line says exactly what the edit did (the editor asked for it on 2026-11-21), read from the edit itself and never from Scarlet's words: a cut's words, struck, after "Took out" ("Takes out" on a call, in amber), or its length when it took out no words; and for any other edit what its steps set, such as a caption's words, the file laid over the picture, how far a zoom goes, a level in dB, a speed or a transition, the first two and how many more. A moment, a spot marked for the editor and an edit whose steps name nothing have no such line. The note is a small dim caption on up to two lines. A pass that stopped early, or finished without checking some of them, hands the editor the flagged cuts it never checked, and such a call says "Not checked yet." before its note. The passage is on the card, folded behind the transcript icon: opened, it sits between the note and the controls, scrolling inside the card when long, and it folds again on the next cut. Until its words arrive it says Loading the words… beside the mark. Opened, it reads whole sentences either side of a ✂ mark where the cut joins, red once applied, amber for a call. A mark holds up to 8 removed words, struck through; a longer cut's mark gives its length and opens its words when clicked. The passage has no speaker or track tags. A note longer than two lines opens in full on a click and folds on the next; there is no button, only the pointer changes over it. Revise, Keep, Done and Apply show R, K, D and A beside their labels as small keys, and Before/After shows \. The other shortcuts (↑ ↓ X) show on hover. ↑ and ↓ step to the previous and next edit or call. From a flagged edit still waiting on the editor, or one of them sent back for revision, they step to the previous and next one that waits, unless the chat lists every edit of its request, however that list came to be open: then they step through them all. ← and → are always the player's, card open or not: they skip 5 seconds, or 1 second with Shift. There is no Close button; Esc closes it. An applied edit has Revise (R), Keep (K) and the × that rejects it. An edit that only left a marker for the editor, such as a spot for footage the project doesn't have, changed nothing in the video: its card says To do, its note leads with what to add, and it has no Before/After, only Revise (R) and Done (D), which records it as Keep does. An applied edit sent back for revision has no card until its new version lands: its note and decisions are about the version on its way out, and its row in the chat says Revising…. It stays open meanwhile, with the message box still aimed at it, ↑ and ↓ stepping on and Esc closing it, and the card comes back on the new version. A revision of an edit that was the editor's to check is theirs to check again, whether or not Scarlet flags it: it is amber and counted on For you, and its row says Revised until Scarlet gives a reason of its own. Scarlet saves why it made every edit. The card above the timeline shows that reason and any listening or viewing cue. When Scarlet's doubt is about a part of the video, the card has a Check pill after the note, like the edit's kind but amber, which plays just that part when pressed and gives its times on hover, and the timeline marks that part in amber, labelled Check, where it is now; the note then leaves out any times Scarlet wrote, which an earlier save may have moved. The chat shows the short summary of what changed. Older edits show their saved note when a separate reason is unavailable. Keep records the review and, on For you, moves to the next flagged edit that hasn't been kept, or after the last of them to the first call of the same request that still waits. On See all (and from any edit Scarlet didn't flag), Keep moves to the next row of the list that hasn't been kept, in its order: an edit Scarlet didn't flag, a flagged edit that still waits or a call that does, going past the ones that have and wrapping to earlier ones, and the card closes once nothing is left to keep. A call has the same actions as an applied edit (the editor matched them on 2026-11-21): Revise (R) and Keep (K), then a small × that rejects it (X) and says "Reject edit (X)" on hover, as an applied edit's does. Keep makes the change Scarlet proposed and Reject edit leaves it out, so the words fit any kind of edit, not only cuts. A revised call shows its version before its note; hovering it shows the earlier version and the note that sent it back. On For you each call moves to the next waiting call and then to any waiting flagged edit; on See all it moves to the next row in that list (edit or call). The last call applies the pass with Scarlet's picks for the rest, or schedules it for when Scarlet finishes checking, leaving any edit it moved on to open. A scheduled pass waits for the editor again if Scarlet then asks about a cut they haven't called. Nothing in the chat applies a pass and nothing holds one back: once no call waits on the editor and no cut is with Scarlet, it goes in by itself, a call changed after the last included. While Scarlet still checks, the line under its calls says "Goes in when Scarlet finishes", as a status with no button. Only an apply that failed offers Retry, under the reason. A suggestion that isn't a dialogue pass opens in the same card on top of the timeline, in the same two rows: Scarlet's words for it, then Before/After, Revise (R) and Apply (A), with Esc to close it. Revise and Apply are the same soft pills, Apply a shade lighter. \ switches Before and After. The suggestion plays as its line in the chat is pressed, and only then: a strip that comes back by itself, after an apply that was refused, is paused. The editor chose this design. In the simple view's chat, each request is a section (`.unit`): a band across the chat, then its work as plain lines under the band. The band has the editor's words on up to two lines and, at its right, where the request stands. It has no name or number, so "Edit 14" in the chat or on the timeline is always an edit Scarlet made. A request about one cut or edit says which before its words, in the tag the message box showed ("Cut 2", "Cut at 2:05"). At the right is the request’s active work time and, when tokens are shown (Settings → Usage), the tokens reported so far. While Scarlet works or asks, the band's right holds Pause and Stop, each an icon alone, and no menu; the moment the pointer rests on one its name shows over it ("Pause editing", "Stop this edit"). Pause holds all editing in the project and becomes Resume ("Resume editing") once it is paused; Stop ends just that request. A word shows once it stopped early ("Stopped", "Couldn't finish", "Paused") or left a suggestion to play ("Suggestion"). Whenever a call or a flagged edit waits on the editor, For you lists what waits without a click and shows the number still waiting. The band's amber dot gives way to the count. A finished request keeps its final active time and token count in the band. Active time excludes time spent waiting for the editor or in the queue and carries over when a run resumes. Hovering the metrics lists every part of the token count. There are no bubbles and no cards. Every link in the chat rests one way, muted with a rule under it (Resume, Retry), and is amber when it needs the editor (Answer). The one exception is the link after what a request made ("See edit"), which is white and semibold with its rule, since it is how the editor reaches the result. A long pass and a one-line revision use the same rows (`.req`). While Scarlet works, what it is on is under the band, for as long as it works and without a click. There is no overall progress bar or percent. First under the band is the one sentence Scarlet said before it began, on what the whole request will come to (`.req-lead`), in the type of its replies and on up to three lines. It is written once, stays as it is while Scarlet works, and leaves when the request is done. It is never shown again as an update, and a request Scarlet began without one has none. Under it is one line (`.req-now`) that says what Scarlet is doing this moment, with a turning ring before it (it fades in and out with motion reduced) and words that shimmer, on up to two lines: the latest call Scarlet made on the project, in plain words that say where ("Reading the dialogue at 12:34", "Checking how 4 joins sound", "Listening to Cut 2"), or Scarlet's own latest sentence when that came after. The next call or sentence takes its place, so it changes every few seconds. Counts the engine keeps in the background (pages of a scan, how far the checked joins reach) and a saved edit don't take the line. While the recordings are transcribed it says so with how far along they are, the one figure there. A request that carries on after Scarlet closed or restarted, or after a pause, says "Picking up where it left off" there until its first call (the editor asked on 2026-11-19 that a restart mid-edit be clear); the hover on Restart to update says beforehand that the edit picks up where it left off. That line is all there is: no stages, no plan, no list of what Scarlet has done, the same for a dialogue pass, a request about one call and any other request. Nothing above the message box says Scarlet is editing. Pause, at a working request's right, stops the work under way in this project, keeps every edit Scarlet saved and starts nothing new; a question waiting on the editor stays, and can be answered meanwhile. It then becomes Resume, a play icon, which picks the paused work up first, where it left off. Only when editing is paused with nothing under way, just requests waiting their turn, does the tray's last line hold Resume, after "Editing paused" in amber. A paused request stays where it was in the chat, with Paused where its band says where it stands (a request with no band says it on its row). Stop this edit, at a request's right, ends just that request, paused or not, and lets the next request start. A question is the band's amber dot, the question under the band and Answer on a line of its own. No row says "Needs your answer" over it. A run that stopped early has its word in the band and, under what it left, its one action: Resume or Retry. What it left is Scarlet's words when it has any, and the action has the line after them; with none, one row says what the run saved ("Nothing saved") and the action follows on that row. "Nothing saved" opens nothing. Why Stop this edit, Resume or Retry failed is the last line of that request's block, wherever the block is. A pass that finished its work but whose closing check for repeats couldn't run hasn't stopped early: its band says it is finished, and one line under its reply says the check didn't run, with Retry after it, which runs that check again. One paused for its transcripts has a row that says how far along they are, as a percent, with Finish when ready after those words (Don't wait once asked, Finish edit once the transcripts are saved). While no transcript is being made the row says so ("Transcript stopped", "No transcript"), and its action is the one that starts it, as on the Media row: Retry or Transcribe. One that saved nothing has no row that says so; the tokens it used, when those show, end its one row. A stopped request that was asked again and has finished since has no Resume. Scarlet's reply sits first under the band: one or two plain sentences that sum up at the highest level what it did, with no times, numbers or lists. Anything Scarlet wants the editor to look at, listen to or decide is in For you, as a flagged edit, or asked as a question, never only in the reply (the editor's decision, 2026-11-17). A reply keeps to two lines however much Scarlet wrote: a longer one ends in an ellipsis, opens in full on a click and folds again on the next, with no button, as a card's note does. A request has one reply: when Scarlet answered the editor's note and then closed the request with a message, the closing message is the one that shows. While the request's list of edits is open, the list takes the place of that reply, and Hide brings it back. A request that changed nothing has no row under that reply. A suggestion waiting to be played is one line: a small play mark, then Scarlet's words for it. The line itself plays it; there is no Play link. What a finished request made is one sentence (`.simple-made`) in the chat's own type with its figures in bold, followed on the same line, for one edit, by an underlined, semibold link in the foreground color. For one edit, "See edit" opens its card on the timeline and shows its selected row in the chat. The link reads "Close edit" while the card is open and closes both on a second click. For several edits with no review rows, "See both" or "See all" is a tab on a line of its own under the sentence, with the rule under it, exactly where For you and See all sit when there are review rows; it is underlined while its list is open, and pressed again it closes the list. While a request has review rows, For you and See all sit side by side above its list and the selected one is underlined. For you is selected by default. See all shows every edit. For you restores the review list and opens the first one waiting, or keeps a waiting edit open if the editor is already on it. One request's list of every edit is open at a time: opening another closes it, so two "Hide" links never stand for one timeline. A list of what needs the editor leaves the others as they are. While Scarlet still works there is no sentence, and the link uses champagne text with a muted gold underline and counts what it opens: "See 42 edits so far", "See 1 edit so far". Opening a list brings its selected row into view, or its first row if none is selected. A sentence that wraps takes the link after its last word. See all is left out while every edit it would list waits on the editor. An edit opened from the timeline then shows in For you. Scarlet builds the sentence from what it counted, so it is right for any request: cuts say how much came out ("Took out 33:51 in 117 cuts"), anything else is counted by what it did ("and made 3 zooms and 1 reframe"), up to three edits that aren't cuts are named ("Made 3 edits: music bed, captions, wrap.") unless they are all graphics, which are counted ("Made 2 graphics."), and a request that made one edit says Scarlet's own sentence about that edit. Spots Scarlet marked for the editor are counted on their own, last ("and marked 2 spots for you"). An edit made in several places is one edit. There is no larger type and no line of counts. ## AI editing agents

Read `docs/AI-AGENTS.md` before changing the prompt, skills, MCP tools, perception, agent hosts or editor preferences. Use [the skill and tool ownership guide](docs/skills-and-tools.md) to decide where new behavior belongs and how to test it.

When the editor reports a mistake in a dialogue cut, or before any change to how Scarlet cuts dialogue, follow `evals/DIALOGUE.md`: read the history of every earlier report and fix first, add the mistake to the ledger with a check, and ship only when every free check passes. A change to what the model reads (a skill, the prompt, a tool's description or result) also ships with its dialogue scorecard beside main's, on the recordings that have a published video: the editor asked for every dialogue cut change to be measured against it (2026-11-18). That standard run is two passes a recording; say what it cost. Ask before starting any larger run of model passes.

- The model makes editorial decisions, the harness (Claude Code, Codex) runs the agent loop, and Scarlet measures the footage, applies edits safely and gives the editor control. Keep them separate so a better model or harness improves Scarlet without changes here.
- Speed is measured from the editor's request to a moment they can judge. Keep tools fast and cached, and render only what changed.
- Only creative decisions reach the editor. Anything they'd have to do by hand is a missing tool or measurement.
- Leave decisions to the model and avoid hardcoded heuristics. The editor gets creative choices and the cuts or edits the model isn't confident about, where a mistake is likely; the model decides which, from Scarlet's measurements. Scarlet's code doesn't flag, stage or decide by a fixed threshold, except to keep an edit safe. A skill can state a specific rule ("a kept silence of 2 s or more goes to review"): skills are the editor's to customize, so a rule there is their decision, and the model follows it. So: the model decides, Scarlet's code measures and keeps edits safe, and a skill holds taste and rules. Scarlet may hand a cut back to the model with a measurement; it doesn't send one to the editor or write the editor's note.
- Give the model everything the task needs: the editor's words as said, where they were looking, notes, the thread and preferences. When it errs, look for missing context before adding an instruction.
- Write for the next model: no fixed pipelines, instructions only for observed failures, and prune rules after each model upgrade.
- The engine builds the one prompt every host uses (`GET /api/tasks/:id/prompt`). Don't build prompts in a host.
- Tools return evidence. When Scarlet overrides the model for safety or because of an editor setting, it reports each override with its evidence. No hidden modes.
- Shape tools to what the harness delivers (`packages/shared/src/capabilities.ts`); never ask the model to judge its own abilities.
- Put tool mechanics in tool descriptions, taste in skills and Scarlet's contract in `SCARLET_INTRO`, each stated once.
- Measure changes that could affect a cut with `evals/`. Never commit user media, transcripts or results.
