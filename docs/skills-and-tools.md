# What belongs in Scarlet and what belongs in a skill

An editor can ask Scarlet to cut a repeated line with an empty skill library. Scarlet can find both takes, show what follows each, place a cut and play the result. A skill can express the editor’s preference for the uninterrupted delivery. The model decides whether that preference fits this line and this brief. Editing or deleting the guide should change the advice the model receives. The same operation on the same project, with the same arguments, settings, task scope and evidence, should still have the same meaning.

## Where a new behavior belongs

| Question | Owner | Example |
| --- | --- | --- |
| What does the editor want this time, and where? | The request and its task context | “Keep the pause before this answer”, the selected passage and version, the cut being revised, or a request to review every cut. The renderer captures the editor’s choice and the engine carries it into the task. |
| Would two editors reasonably want different results from the same footage? | An editable skill for a recurring preference. The model makes the choice for this request. | How tight an interview feels, which reaction earns a hold, whether to keep a restart, how to break a caption or frame a demo. A specific instruction from the editor takes precedence over a guide’s default. |
| What can Scarlet measure or do on request? | The engine, media and timeline packages, exposed to the agent through MCP tools | Identify repeated words, measure room tone or sync, map source words to the edited timeline, crop a clip, generate caption cues, render a version. A tool can perform several mechanical steps for one editorial choice. |
| What must hold even if the model chooses a different tool or never opens a guide? | Product code at the point that applies the operation. Use an editor setting for a standing control. | Validate versions and ranges, respect protected footage, constrain a revision to its cut, apply a dialogue review setting and report the reason for any adjustment. The editor’s selection bounds the **final removal ranges**, including edge adjustments. |
| What does the model need to know to use Scarlet? | The shared prompt for product-wide behavior and task context. The tool description, schema and result for individual operations. | The prompt explains versions, review and how to address the editor. The tool explains units, accepted ranges, defaults, required evidence and what it saved. A skill may name a useful tool to help the model find it. |
| Who controls the run and what the editor sees? | The harness runs the model and tool loop. Scarlet supplies the available tools and presents the actual work. | Capabilities and tool settings determine what a session can use. Task events and saved changes drive progress, calls, playback and undo. Reading a guide grants no permissions. |

A setting and a skill can address the same subject. “Leave enough time to read a result” is guidance the model weighs against the picture. “Send filler removals to me for review” is a setting the engine must honor when it receives a classified dialogue plan. A shorter pause in a skill cannot authorize an operation that the setting holds for review. [Dialogue preferences](../packages/shared/src/dialoguePreferences.ts) · [Engine enforcement](../apps/server/src/services/changes.ts)

An explicit tool option can also encode a convenient preset. For a screen demo, the model can ask for a camera inset and supply its own framing or use the tool’s documented default. Scarlet computes the overlap and transform. The editable guide says when the speaker should stay in the corner. The same inset is available to an editor who uses a different guide. [Screen-framing skill](../skills/frame-screen/SKILL.md) · [Inset implementation](../packages/mcp/src/sync-layout.ts)

For automatic editing, say what the editor delegates. Setting the length of a crossfade at a chosen cut delegates a mechanical operation. Shortening an additional pause or choosing another performance changes what plays. Those choices need either the model’s decision for that moment or a setting that accurately describes the automatic edit and honors the editor’s exceptions. A required quality check belongs to the task that promises it. Its scope comes from the editor’s request and the footage that task changed.

## How a skill reaches an edit

- **Library.** All projects share one library. The Markdown files under `skills/` supply the shipped text. The server build embeds them and the engine seeds ordinary, versioned library entries. A later release updates untouched stock text. An editor’s content change makes that copy theirs. Disabling a guide preserves its disabled state across updates, and deleting a stock guide through the editor keeps it deleted. [Bundling](../apps/server/scripts/gen-skills.mjs) · [Seeding and updates](../apps/server/src/services/skills.ts)
- **No guide pinned.** The initial editing prompt lists enabled workflows whose names match the bundled set with their descriptions and a lookup instruction, including customized copies with those names. Other enabled skills, such as house rules, are included in full. Retained copies of retired stock workflows still load by lookup. Legacy quick actions are available by lookup or explicit selection. [Prompt selection](../apps/server/src/services/skills.ts)
- **One or more guides pinned.** The task stores the selected skill IDs. Product dialogue shortcuts also record the requested operation separately, including after a queue reword or an answer that changes it. The initial skill section contains only the enabled selections, in full. Other enabled guides, including house rules, remain discoverable through `skills_list`. The lookup lists descriptions or returns one guide by ID or exact name. The pin selects instructions and the lookup reads them. Tool permissions and edit scope have separate owners. [Composer](../apps/web/src/components/agent/Composer.tsx) · [Prompt assembly](../apps/server/src/services/tasks.ts) · [Skill lookup](../packages/mcp/src/server.ts)
- **Revision and creation.** An editor can write a skill in Settings or ask Scarlet to revise one. A `skill_edit` task receives the existing guide and product contract, can ask questions, and can save prose only to the selected skill. An editor can also request `skill_from_change` for an approved change. The task can read its approved example and resulting version, ask a question, report progress and save the requested guide. The approved version and requested name identify the example and destination. The model supplies a description and reusable instructions. Scarlet owns the write, version history and provenance. [Skill routes](../apps/server/src/routes/skills.ts) · [Skill-edit prompt](../packages/mcp/src/prompt.ts)

A house guide that says “always protect the sponsor read” can drop out of the initial prompt when the editor pins a different guide. If the product promises protection, represent the protected footage in task or project data and check it when saving the edit. [Selection integration tests](../apps/server/src/workspace.test.ts)

For contributors editing a guide, put its trigger in the frontmatter description and the desired editorial result in the body. Explain how the footage or the brief can change that judgment. Keep field definitions, numerical limits imposed by the API, retry instructions and permission rules with the tool. A pacing guideline may contain a number an editor can change. A frame boundary or an enforced limit needs an implementation and a test. [All shipped workflows](../skills/README.md)

## How to verify a change

- For a new **operation**, call it with no skill selected, after reading a guide, and with a different guide pinned. Hold the tool arguments, settings, scope and evidence constant. Compare which tools are offered and what gets saved or staged. Exercise settings and scope through each applicable write path, including final adjusted ranges. [MCP integration tests](../packages/mcp/src/server.test.ts) · [Engine tests with an empty skill library](../apps/server/src/aiBoundary.test.ts) · [Dialogue planning tests](../packages/mcp/src/dialogue-plan.test.ts)
- For **skill delivery or authoring**, check the actual prompt, tool list and saved destination for the task. Include custom, disabled, deleted and explicitly pinned guides. For a shortcut, follow the request through the composer, queue, engine and tools. [Library lifecycle](../apps/server/src/services/skills.test.ts) · [Prompt and selection integration](../apps/server/src/workspace.test.ts) · [Command parsing](../apps/web/src/stores/skills.test.ts) · [Authoring routes](../apps/server/src/app.test.ts)
- For a change to **editorial behavior**, compare the same footage and brief before and after. For dialogue, replay saved plans to isolate a tool change and run model trials to evaluate a skill or prompt change. Score the cut, review decisions and time to the first reviewable edit. Keep project-derived data outside the repository. [Editing evaluations](../evals/README.md)

## Where the rules are enforced

| Behavior | Product contract and regression coverage |
| --- | --- |
| Dialogue shortcuts and pinned skills | The built-in `/dialogue-pass` requests a dialogue cut. Older libraries can also use `/first-cut-dialogue` with their saved guide. The built-in `/tighten-pauses-here` requests pause decisions within a selected or playhead-bounded passage. The engine stores the operation independently of the guide IDs. Typing the built-in command still works when the shipped guide is missing or disabled. A custom guide owns its exact command name. Only the full-pass operation owns completion-time repeat verification, within that pass’s scope. [Command resolution](../packages/shared/src/threads.ts) · [Task lifecycle](../apps/server/src/services/tasks.ts) · [Integration tests](../apps/server/src/workspace.test.ts) |
| Classified dialogue removals | Cut, Suggest and Off apply when the engine saves classified removals. If a kind is restricted, a raw agent proposal that removes recorded footage must use the classified dialogue path or explicitly identify an ordinary content edit. A dialogue pass must use the classified path. This covers clip trims, ripple deletions and assembly from selected pieces of a recording. A complete source with a synchronized secondary recording can still be assembled. [Engine](../apps/server/src/services/changes.ts) · [Source comparison](../apps/server/src/services/dialogueRemoval.ts) · [Boundary tests](../apps/server/src/aiBoundary.test.ts) |
| Selection, pauses and take identity | Scarlet bounds the saved cuts after edge placement and frame alignment, preserves explicit keeps, and uses the selected occurrence when a line repeats. The join check can measure another occurrence for the model to consider. A short wordless interval between cuts stays in the edit. Pause tightness can shorten an undecided, measured quiet gap in the part being saved. An explicit duration, keep or protection takes precedence. [Planner and tests](../packages/mcp/src/dialogue-plan.test.ts) · [Selection mapping](../packages/shared/src/cutScope.ts) · [Settings](../apps/web/src/components/shell/DialogueSettings.tsx) |
| Skill creation and Learnings | A skill-from-change task reads the approved change as an example. A learning check can propose a rule for adoption. The editor reviews the rule, target and any quoted text it would replace. An approved save is limited to that rule and those passages. Direct editing of a guide in Settings remains available. [Authoring routes](../apps/server/src/routes/skills.ts) · [Learnings](../apps/server/src/services/learnings.ts) · [Engine tests](../apps/server/src/app.test.ts) |
| Harness capabilities | Available tools and results reflect the media types the harness can deliver. When images are unavailable, comparisons can still return text or supported audio. A picture review receipt records which views were delivered before a verdict can count as inspected. [Integration tests](../packages/mcp/src/tools.test.ts) · [Review and tools](../packages/mcp/src/server.ts) |
